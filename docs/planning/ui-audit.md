## デザインを移す単位

**事実:** 現行Androidは生成り背景、紙の繊維とちぎり端、薄い影、テープ、太い黒い金額、ライムのマーカー/選択面、相棒シール。`Brand.kt`は背景`#EEEDE6`、面`#FAF9F3`、文字`#17191B`、ライム`#D2ED70`、赤`#B84638`。ホーム金額は等幅数字。旧iOSは背景`#F3F0E9`・赤茶`#B13E36`・角丸カードで、共通コンポーネントや紙素材の構成がない。

**判断:** 配色・紙・余白・金額階層・マスコット資産をiOSにも揃える。画像は紙質とキャラクターに限定し、金額・入力・ボタン・日付・グラフは実データのアクセシブルな部品にする。iOSのsafe area、戻る、シート、文字拡大に合わせて再配置し、1080×2400画像全体の引き伸ばしはしない。主要操作は最低44pt、選択は色＋チェック/ラベルで示す。紙の輪郭がタップ判定や本文を削らないこと。

**判断:** 優先順位は「金額が増える→今何を記録しているか→終了できる→振り返る」。装飾、レシート印字、品物演出は金額の読み取りを妨げない。アプリ内計測値は太い等幅数字、小数2桁を小さくし、桁上がりでも位置を跳ねさせない。アニメーション用の値加算を記録値に使わない。

## 値札の設定：方式から選び、対応する見た目を確かめる

**判断（技術検証を条件とした設計）:** 設定の「値札の設定」は次の順序を固定する。

1. **表示方法**: `PiP / 小さなウインドウ`、`Live Activity / ロック画面など`。各選択肢は表示先と「利用可能」「未許可」「この端末では利用不可」「検証中」を説明する。後二者は使用中に見せず選択不可。未対応方式を選ぶ偽の成功操作を置かない。
2. **この方法のデザイン**: 選択方式で対応するカードだけを提示。選択即保存、`PiP用`と`Live Activity用`の保存を独立させ、切替で以前の好みを失わない。
3. **プレビュー**: 金額見本、表示先の枠、SPEND/INVEST、少額/桁数大、文字サイズを確認。実測の更新特性を表現し、見本は記録しないと表示。
4. **表示を試す**: 記録開始とは独立した短い試用。成功/非表示/競合の結果と再試行・別方式の導線。実際の表示確認ができて初めて設定完了。

| 方式 | デザイン候補（判断） | プレビューと移植上の境界 |
| --- | --- | --- |
| PiP | A ちぎり値札、B インクメーター、C フロストラベル、D 相棒シールを候補。実装・審査成立後に対応と表示 | OSのウインドウ枠/操作がある前提の内側に紙を描く。独自形状の透明オーバーレイとは区別。実際の最小/拡大サイズ・余白・OS操作重なりを確認。金額を最優先しDの相棒は文字領域を奪わない |
| Live Activity | 紙/インクの簡潔な2案を初期候補。ロック画面・Islandの面ごとに縮約するデザイン群 | ロック画面、Island展開/コンパクト/最小の各見本を分ける。大きな紙・透明感・外にはみ出すシールをそのまま保証しない。最小表示は識別に必要な記号、広い面は金額＋活動。表示更新が止まる条件まで試す |

**未検証:** PiPの用途適合・他アプリの動画との共存・バックグラウンドでの金額描画、Live Activityの任意の円金額の更新頻度と持続性、各面の表示可能寸法。方式確定は技術検証担当の結論に従う。アプリ内の滑らかな見本をそのまま「他アプリでも100ms更新」と説明しない。

**判断:** Live Activityで動き続ける円金額を保証できなければ、確認時点の金額と更新状態を分かる形にする。滑らかに見える架空額を表示しない。この場合、Live Activityだけで主目的を満たしたとは評価しない。PiPで条件を満たせるなら「他アプリ利用中に増える」導線を主導線にし、失敗時は計測自体の状態を保持してアプリ内確認へ戻れるようにする。検証前の初期方式は決め打ちしない。

**判断:** 計測中にスタイル変更はプレビューと次回表示へ反映。方式変更は「次回の表示から」と明示して進行中の計測を分断しない。手動で値札を閉じた状態と記録終了を混同させず、必要なら「値札は非表示・計測中」と本体へ示す。

## 実装前に残る確認

UI再現は実計測の前に固定サンプルデータで先行する。紙・ロゴ・配色・ナビゲーション・各画面・値札方式選択とプレビューを作り、CI画像を親がAndroidと比較してレビューする。PiP PoCは並行し、実寸・OS操作・開始導線は結果に応じて調整する。実機で動く金額は製品合格条件であり、UI着手の条件ではない。デザイン選択の美しさだけでPiP/Live Activity成立としない。今回閲覧した9/14画像にない実行中・単票・通帳・会話の代表状態は、既存コードと追加の証拠で次工程に補う。iOS既存画面の指摘はコード監査によるもので、レンダリング不具合の実機再現ではない。
