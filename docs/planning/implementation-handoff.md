```text
MoshiDopa_iOSの docs/ios-redesign-plan.md と参照先の3調査書に従い、
P1（最小ネイティブビルド・CI・画面撮影）を整備し、
P2A（Android UI再現）を先行、P2B（PiP金額カウンターPoC）を並行して実装してください。
最新Androidは読み取り専用の基準として扱い、android-baseline.jsonとの差分を確認してください。
旧iOSのGit履歴を保持し、作業ブランチ上で進めてください。

統括はAstra Mid、中間はSol Mid、末端はLuna MAX。
サブエージェントは必要な独立作業だけ、最大3体、モデルと推論強度を明示してください。
親自身が設計・コード・画像・CIをレビューし、問題を修正して再確認してください。

金額の連続増加を中核とし、時間のみの表示で代用しないでください。
まず固定サンプルデータでAndroidの紙素材・ロゴ・配色・ナビゲーション、ホーム・履歴・設定・
明細・初回案内・もしも便を再現し、親がCIの画像・動画を比較して修正してください。
値札設定の方式選択・対応デザイン・面別プレビューも先に作ってください。
見本データは本番記録へ保存せず、実計測・保存を後から接続できる構造にしてください。
独立してPiPを試作し、本体のユーザー操作から開始、終了・保存は共通SessionServiceで処理してください。
PiPの実寸・OS操作との重なり・外部表示開始導線はPoC結果に応じて調整してください。
GitHub Actionsで実際にSimulator build/test/画面撮影とiphoneos Release未署名buildを実行し、
commit付きの実行URL・ログ・xcresult・画面・ビルド成果物を残してください。
未署名成果物をそのまま実機インストール可能と扱わないでください。

PiPの背景更新・SNS音声共存・Shortcuts・署名は実機検証と分けてください。
実機を使えない場合は試験用ビルドと再現手順まで完成させ、P2Bは未検証と報告してください。
実機待ちでP2AのUI再現を止めず、画面比較と親レビューまで完成させてください。
実施していない試験を成功扱いせず、モックで動く画面と実機の背景金額表示を区別してください。

完了条件はP1の実CI成功、P2Aの画面再現と親の視覚レビュー完了、
P2B実装の親レビュー完了、実機試験可能な成果物と手順の整備、
実施できた試験結果と未実施項目の明確な報告です。
App Store提出とmainへのマージはこのGoalに含めません。
```

このGoalの成果物引き渡しと、製品のP2B合格は別。未実機検証で前者を終えても、後者の合格は記録しない。次のGoalではP3の外部連携とP4の実データ統合、P5の仕上げへ進む。全体の製品合格にはUIと計測・外部表示の両方の検証が必要。
